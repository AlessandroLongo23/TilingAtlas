# Marek Discord knowledge vault — design

Date: 2026-07-16
Status: approved (AL, 2026-07-16), ready for implementation

## Goal

Bring the Discord conversation with Marek Čtrnáct into this repo as an Obsidian vault, so the
tilings knowledge he shares (notation, the combinatorial engine, scripts, images) can be archived
and then distilled into curated notes. The vault has two layers: a raw archive of the chat, and a
curated knowledge layer built on top of it that links back to the source messages.

## Decisions (settled with AL)

- **Layered vault.** Raw chat archive layer + curated knowledge layer, not one or the other.
- **Export via DiscordChatExporter (DCE).** AL runs it locally; CC only builds the tooling and guide.
  AL accepts that using a user token to export DMs is against Discord's ToS in principle and standard
  for personal archival in practice.
- **Raw stays local.** The raw export, generated archive notes, and media are gitignored. Only the
  curated knowledge layer and the tooling are committed. Consequence, accepted: knowledge notes
  deep-link to archive notes that exist only on AL's machine; on a fresh clone those links dangle
  until AL re-exports and re-runs the importer.
- **Scripted importer (approach B), not full auto-classification.** A zero-dep Node `.mjs` converts
  DCE JSON to archive notes. No regex-based auto-filing of "notation"/"code" into the knowledge
  layer — that is done by hand with CC's help, because auto-classification at single-DM scale makes
  more noise than signal.

## Layout and git boundary

Vault root at repo top level, `marek-vault/`, so Obsidian opens it as a vault.

```
marek-vault/
├─ .obsidian/              committed minimal config; volatile files (workspace*, cache) ignored
├─ 00-start-here.md        map-of-content
├─ how-to-export.md        the DCE + importer runbook
├─ archive/               GITIGNORED — one note per day, generated by the importer
│   └─ YYYY-MM-DD.md
├─ attachments/           GITIGNORED — images + files Marek sent
├─ knowledge/             COMMITTED — the curated layer
│   ├─ notation/          Conway symbols, vertex figures, "čtrnáct" naming, palette JSON schema
│   ├─ algorithm/         dual-search, half-edge gluing, WL/DFA canonical form, prune, develop
│   ├─ concepts/          tilings theory: k-uniform, vertex configs, duals
│   ├─ scripts/           annotated write-ups of scripts he sent, linked to archive + attachments
│   └─ glossary.md        term → one-line def → link to the deep note
├─ questions/             COMMITTED — open questions / things to ask Marek
├─ templates/             COMMITTED — note templates (concept, script, daily)
└─ _raw/                  GITIGNORED — DCE dumps the JSON export here
```

Committed: `.obsidian/` (minimal), `00-start-here.md`, `how-to-export.md`, `knowledge/**`,
`questions/**`, `templates/**`, and a per-vault `.gitignore`.
Gitignored (via `marek-vault/.gitignore` and/or root `.gitignore`): `_raw/`, `archive/`,
`attachments/`, `.obsidian/workspace*.json`, `.obsidian/cache`.

Cross-linking note: Obsidian wikilinks resolve only inside the vault. Links to existing repo files
(`tools/ctrnact-oracle/…`, `docs/ctrnact-*`) use plain relative markdown links, which still open but
do not appear in the Obsidian graph.

## The importer — `scripts/import-marek-chat.mjs`

Zero-dep Node, matching the existing `scripts/*.mjs` tooling (`status.mjs`, `docs-check.mjs`).

Input: `marek-vault/_raw/*.json` (one or more DCE JSON exports of the Marek DM).
Output: `marek-vault/archive/YYYY-MM-DD.md`, one note per calendar day (local time).

Behavior:
- Each message renders as: timestamp, author, content (Discord markdown passes through as-is,
  including fenced code blocks), then attachments.
- Media: DCE with `--media` rewrites attachment URLs to local paths. The importer copies/maps those
  files into `attachments/`, dedupes by content hash, embeds images as `![[attachments/<file>]]`,
  links other files (scripts, PDFs) as `[[attachments/<file>]]`.
- **Block anchors.** Every message ends with a stable `^msg-<id>` block id derived from the DCE
  message id. This is what makes source-tracing real: a knowledge note embeds
  `![[archive/2026-07-15#^msg-123]]` to pull the exact message inline.
- Idempotent: a run fully regenerates `archive/` and refreshes `attachments/`; it never writes into
  `knowledge/`, `questions/`, or `templates/`. Re-export → re-run is safe.
- Frontmatter per daily note: `date`, `message_count`, `participants`, `source_export`.
- Reactions and reply-references: included compactly (reactions as a trailing line, replies as a
  quoted pointer) but kept minimal.

Failure handling: if `_raw/` is empty or holds no valid DCE JSON, the importer prints a pointer to
`how-to-export.md` and exits non-zero without touching the vault. Malformed individual messages are
skipped with a counted warning rather than aborting the whole run.

## The export guide — `marek-vault/how-to-export.md`

Verified against DCE docs 2026-07-16. Covers:
- Install: Docker (`tyrrrz/discordchatexporter`, no host .NET needed) as the low-friction path, or
  native CLI zip from releases + `brew install dotnet-sdk` (.NET 6.0+ runtime).
- Token (macOS): ⌥+⌘+I in the browser client → Console → the webpack token snippet. Carries DCE's
  own ToS warning verbatim.
- DM channel id: Settings → Advanced → Developer Mode, then right-click the DM → Copy Channel ID.
- Export command: `export -t <token> -c <channelId> -f Json --media --reuse-media -o marek-vault/_raw/`.
- Then `node scripts/import-marek-chat.mjs`.

## Synthesis pass (post-export, iterative with CC)

Once AL exports and imports, CC helps build `knowledge/` from the archive: notation → `notation/` +
`glossary.md`; the engine explainer → `algorithm/` cross-referenced to the real
`tools/ctrnact-oracle/` code; a per-script annotation in `scripts/`; open questions in `questions/`.
Seeded now: CC pre-populates stubs in `notation/`, `algorithm/`, `concepts/` from what this repo
already documents about the engine, so the vault opens to a real skeleton rather than empty folders.

## Out of scope

- Auto-classification of chat content into knowledge notes (approach C, rejected).
- Committing raw chat or media to git.
- Any handling of servers/group DMs beyond the single Marek DM (can extend the importer later; the
  channel-id argument already generalizes).
